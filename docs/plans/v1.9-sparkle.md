# v1.9.0: Sparkle auto-update [13]

Goal: a DMG install updates itself in place, safely, with no Gatekeeper step and no
Keychain prompt. Widgets [25] follow as v1.10.0 (D-010). Design choices: D-011.

## Design

- Sparkle 2.10.1 via Swift Package Manager in project.yml (exact version). The app stays
  unsandboxed, so no Sparkle XPC services are enabled.
- Info.plist: `SUFeedURL` = `https://github.com/workshop144/claudeglance/releases/latest/download/appcast.xml`,
  `SUPublicEDKey` (EdDSA public key), `SUEnableAutomaticChecks` YES (no first-run permission
  dialog; Settings has the off switch), `SURequireSignedFeed` YES and
  `SUVerifyUpdateBeforeExtraction` YES. Updates are offered, never silently installed.
- `CFBundleVersion` = `CURRENT_PROJECT_VERSION` = `$(MARKETING_VERSION)`; it was empty, and
  Sparkle compares it with the appcast's `sparkle:version`.
- The updater starts only when updating is safe (`UpdatePolicy`, unit-tested):
  - app inside `/nix/store` (read-only): off, Settings says Nix manages updates;
  - not signed with a Developer ID from team Q4PR8D5TG8 (dev-install, Xcode runs, ad-hoc
    fallback builds): off, Settings says this build does not self-update.
- Background-app etiquette: the app is LSUIElement, so the user driver delegate opts into
  gentle scheduled reminders and brings the app forward when an update is shown.
- Settings: one row, "Automatically check for updates" (toggle) plus a "Check now" button,
  or one line of text when the policy turns updates off. Menu: no new item.

## Release pipeline

- Secret `SPARKLE_ED_PRIVATE_KEY` (Sparkle's base64 private seed). A signed release fails
  if it is missing, so a notarized build never ships without an appcast.
- After "Check Gatekeeper accepts the build": download Sparkle 2.10.1's tools (sha256
  pinned), sign the stapled DMG, write appcast.xml with `scripts/make-appcast.sh`
  (version, DMG URL, length, edSignature, minimum macOS, release notes from CHANGELOG),
  sign the feed, then verify both the DMG signature and the feed against the
  `SUPublicEDKey` in the built app's Info.plist. A key mismatch fails the release.
- appcast.xml is uploaded as a release asset next to the DMG. `releases/latest/download`
  always serves the newest release's feed, so CI never commits to the repo.
- Homebrew cask gains `auto_updates true`, so `brew upgrade` leaves a self-updated app alone.

## Keychain

The credentials item trusts the app by its designated requirement, which for a Developer
ID build is the bundle id plus team, not the binary hash. A Sparkle update keeps the same
requirement, so no prompt. 1.8.3 to 1.8.4 prompted once because ad-hoc to Developer ID
changed the requirement. Live check: 1.9.0 updating to 1.9.1 must not prompt.

## Operator

1. Key: generated on n0 2026-11-10 (login Keychain, account `claudeglance`), exported to
   ~/.config/claudeglance-signing/sparkle_ed25519.key.
2. Run ~/.config/claudeglance-signing/set-sparkle-secret.sh, back the key up to LastPass.
3. Merge, tag v1.9.0. Then tag a v1.9.1 and watch 1.9.0 offer and install it.
