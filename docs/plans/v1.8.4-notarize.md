# v1.8.4: Developer ID signing and notarization

Goal: the DMG, Homebrew cask and flake install open with no Gatekeeper warning. See D-009.

## Code (this PR)

1. release.yml archives with `CODE_SIGN_STYLE=Manual` and ExportOptions.plist exports
   manually with the "Developer ID Application" certificate. Automatic signing needs an
   Xcode account, which CI does not have.
2. After the DMG is built: sign it, notarize it, staple it.
3. Gate: `stapler validate` on app and DMG, `spctl --assess` on both. A rejected build fails.
4. Hash the DMG last, so the cask pins the stapled bytes.
5. README drops the quarantine steps for 1.8.4 and later; CHANGELOG warns of the one-time
   Keychain prompt after the signature changes.

## Operator (before tagging v1.8.4)

1. Create a Developer ID Application certificate for the team and export it as a .p12.
2. Create a team App Store Connect API key (Users and Access, Integrations, Developer role)
   and download its .p8. Notarization uses it instead of an Apple ID app-specific password:
   team scoped, no iCloud access, revocable on its own.
3. Set repo secrets: APPLE_CERTIFICATE_1 (base64 .p12, or first half),
   APPLE_CERTIFICATE_2 (second half or empty), APPLE_CERTIFICATE_PASSWORD, APPLE_TEAM_ID,
   APPLE_API_KEY (.p8 text), APPLE_API_KEY_ID, APPLE_API_ISSUER.
4. Merge, tag v1.8.4, watch the release run show "building a NOTARIZED release".

## Verify after release

- `spctl --assess --type execute -vv /Applications/ClaudeGlance.app` says "Notarized Developer ID".
- The tap's cask has no caveats block.
- Then re-pin the flake (`scripts/update-flake.sh 1.8.4`).
